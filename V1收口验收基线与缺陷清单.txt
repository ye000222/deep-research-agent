DeepResearch Agent V1 收口验收基线与缺陷清单
============================================
记录时间：2026-09-14（Asia/Shanghai）

一、收口原则
------------
在真实端到端验收通过前冻结新功能和大范围调度/预算重构。后续每次修改必须同时提供：
1. 一个可复现的失败输入；
2. 一个同边界回归测试；
3. 一次同配置端到端复验；
4. 对覆盖率、P1 覆盖率、交叉验证和关键缺口的前后对比。
单元测试、Golden 合成数据或页面显示为绿色，不能单独宣称 V1 通过。

六、最新已修复的模型问题
------------------------
官方 api.deepseek.com 下的 DeepSeek 模型名称不再硬编码为两个版本；所有大小写无关的
deepseek-* 别名都会把 Planner 的 reasoning_enabled=False 转成 thinking={type:disabled}。
这修复了 deepseek-flash 造成的 Planner 隐藏推理耗尽输出预算问题，但必须用新 Run 做
真实确认。兼容地址和其他模型不会注入 DeepSeek 专有参数。

七、V1 通过条件
---------------
在同一模型、代理、研究目标和预算配置下，连续 3 次新 Run：
- 不出现 MODEL_NETWORK_ERROR、MODEL_TIMEOUT、MODEL_OUTPUT_TRUNCATED、
  PLAN_OUTPUT_BUDGET_EXCEEDED、SEARCH_TRANSPORT_RETRY_PENDING；
- 进入报告阶段并生成可追溯报告；
- 总体覆盖率 >= 85%；P1 覆盖率 >= 80%；交叉验证 >= 70%；关键缺口 = 0；
- 失败/重试/预算让出均有可解释事件，且没有早停吞掉未处理问题。

八、真实验收授权边界
--------------------
真实 Run 会把用户研究目标和检索词发送到已配置的 DeepSeek 与搜索服务，并消耗调用额度。
在用户明确确认之前，只进行本地检查和合成端到端测试，不擅自发起该外部调用。

十一、真实三连收口门禁（已实现，待授权运行）
----------------------------------------------
新增 scripts/verify_v1_real_runs.py，并接入 scripts/release_gate.py --v1-closeout。
门禁只读取同一 owner 最新连续三次 Run，并要求研究目标、模型、凭据版本、预算、评分规则、
Prompt、图结构和 source_revision 完全相同；source_revision 不允许 development/unknown。
每次 Run 必须是 completed/terminal/quality_met，恰有一份 verified 报告，报告开始、验证、
运行完成事件齐全且无 run.failed，同时满足覆盖率 >=85%、P1 >=80%、交叉验证 >=70%、
关键缺口 = 0。静态 Release Gate 明确标记为 static_release_checks，不能冒充真实收口。
真实收口模式禁止所有 --skip-* 参数，并强制提供非 development/unknown 的候选代码版本，
避免跳过本地门禁或用旧版本运行替当前代码背书。

以当前数据库最新三次运行反向验证时，门禁按预期失败：三次虽均已生成 verified 报告，
但 termination_reason 不是 quality_met，覆盖率、P1、交叉验证和关键缺口均未同时达标，
且旧运行没有可识别 source_revision。这证明门禁不会把旧的受限报告误判为 V1 通过。

启动三次新的真实验收仍需用户单独明确授权；授权前不调用 DeepSeek 或搜索服务。
