研究空转与吞吐优化实施记录
============================

日期：2026-09-11
目标：在不降低证据质量门、来源丰富度和全局预算约束的前提下，消除单个 Research Plan 问题上的重复空转，提高有效搜索、页面读取和证据抽取吞吐。

一、现场诊断
------------

诊断 Run：01a08ff2-076e-734a-84c6-5326d747ff00

当页面长时间停留在约 19% 时，数据库和事件流显示：

1. 全局模型预算仍剩余约 96,000 Token，但问题级预分配被当成硬上限。
2. 证据抽取调用的计算额度略高于该问题预分配时，reserve_model_tokens 拒绝预留。
3. 拒绝发生在并行页面预取之后，导致网页已经下载，却没有进入证据抽取和页面结算。
4. 后续调度只要看见缓存候选就始终 reuse_only，同一批候选被反复预取。
5. 现场累计约 188 次 search.reused、167 次以上低信息增益，但实际外部搜索仅 8 次、有效抽取仅 1 次。
6. 候选中还包含视频页、登录页和文档聚合页，进一步浪费页面读取时间。

结论：这不是单纯的模型或网络慢，而是“问题级硬配额 + 无限缓存复用 + 无效页面预取”组成的空转闭环。

二、根治改动
------------

1. 问题级 Token 配额改为软分配

- question_token_budgets 只作为轮转公平目标，不再作为单次模型调用的硬拒绝条件。
- 某问题超过预分配时，可从该 Run 的全局剩余 Token 池借用。
- max_tokens、未结算预留和 Writer 预留仍是硬边界，不放松总预算安全。
- 增加 budget.question_allocation_borrowed 审计事件，并记录 borrowed_tokens。

2. 缓存复用与新搜索交替

- 偶数次尝试优先复用未读候选或已保存页面，节省搜索和网络开销。
- 奇数次尝试强制使用新的查询变体，再合并仍可用的缓存候选。
- 这样既利用已有材料，也避免围绕同一批低收益候选无限循环；外部搜索预算会按实际搜索推进。

3. 页面读取前硬过滤明显无效来源

- 在 HTTP 读取和并行预取之前过滤视频站、登录页、搜索结果页和文档聚合页。
- 搜索结果仍保留审计记录，但不再消耗页面槽位和网络时间。
- 保留 NIST、政府、大学、厂商技术资料、开放论文等可稳定归因的正文页面。

4. 无候选快速返回

- 过滤后没有可读候选时立即以 zero_results 结束本次尝试，不再无意义申请页面槽位。
- 下一轮会切换到新的查询变体，而不是继续读取同一批无效 URL。

三、准确性与速度的平衡
----------------------

- 准确性：原有覆盖率、来源质量、交叉验证、引用支持度和关键缺口质量门保持不变。
- 丰富度：强制穿插新搜索，避免材料长期局限在首次候选池。
- 速度：缓存复用仍保留，但最多连续一次；明显无效页在网络读取前被拦截。
- 公平性：问题调度仍按未完成问题轮转，软借用不会取消其他问题的未来额度保护。
- 终止安全：全局 Token、搜索次数、读取页数和 Writer 预留仍负责硬停止；真实资源耗尽时仍允许 completed_with_limitations，空转不再伪造资源耗尽。
