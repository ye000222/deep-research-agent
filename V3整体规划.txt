对，V3 需要重新规划，而且这次应该把“**架构收敛**”本身设为 V3 的一级目标，而不是只追求把 V2 没做完的 Active Gap Closure 接上。

我建议把 V3 的正式定位改成：

> **V3 = Autonomous Research Orchestrator + Architecture Consolidation**
>
> 一边完成真正的自主研究闭环，一边主动减少 V1/V2 遗留下来的双轨控制、中间投影、临时桥接和重复状态。

换句话说，V3 成功的标准不是“新增了多少模块”，而应该是：

> **能力更完整，但核心抽象更少，状态归属更清楚。**

---

# 一、先冻结 V2，不再继续扩展

V2 历史状态建议正式固定为：

| 阶段 | 状态 |
|---|---|
| V2.0 Claim Architecture | ✅ Complete |
| V2.1 Semantic Claim / AP | ✅ Core Complete，保留验证债务 |
| V2.2 Corroboration / Verification / Conflict | ✅ Complete |
| V2.3 Evidence + Semantic Runtime | ✅ Development Complete |
| V2.4 Step 1 Gap | ✅ Complete |
| V2.4 Step 2 GapResearchIntent | ✅ Complete |
| V2.4 Active Gap Closure | ❌ 未完成，迁移至 V3 |
| V2.5 Variance Reduction | ⏸ 不继续，后续按数据决定 |

从这里开始，不再创建：

```text
V2.4 Step 3.1
V2.4 Final Fix
V2.4 Control Revision
```

V2 就冻结在这里。

---

# 二、V3 的核心目标改成两个

以前我们主要想着：

> 把 Active Gap Closure 做出来。

现在应该同时有两个目标：

**目标 A：真正自主闭环**

```text
Question
→ Research
→ Evidence
→ Semantic State
→ Gap
→ New Research
→ New Evidence
→ Re-evaluation
→ Continue / Stop
```

**目标 B：架构瘦身**

最终系统不能继续保留：

```text
旧 scheduler
+
新 scheduler

旧 continuation
+
新 continuation

Shadow snapshot
+
HandoffBundle
+
RunStateSnapshot
+
AuthorityView
+
一堆中间 truth projection
```

V3 应该把这些逐渐收敛到一个清楚的主架构。

---

# 三、V3 只允许 5 个一级核心抽象

这是这次规划最重要的限制。

我建议整个 V3 长期只保留下面五个真正的一等概念。

| 核心抽象 | 职责 |
|---|---|
| `ResearchRunState` | 整个 ResearchRun 当前完整状态 |
| `ResearchWork` | 一项需要完成的研究工作 |
| `WorkAttempt` | ResearchWork 的一次具体执行 |
| `ResearchOrchestrator` | 调度、预算、恢复、继续/停止 |
| `SemanticEngine` | Evidence → semantic state |

其他概念尽量作为：

- 内部 DTO；
- immutable snapshot；
- derived projection；
- service；
- adapter；

而不是继续升级成永久的一等架构实体。

---

# 四、取消独立 ExecutableResearchObjective 作为一级实体

之前设计：

```text
GapIntent
→ ExecutableResearchObjective
→ WorkItem
→ Attempt
```

从理论上很干净，但对当前项目来说容易过度设计。

V3 建议直接收敛成：

```text
Gap / Planner
      ↓
ResearchWork
```

`ResearchWork` 自己包含冻结的 objective snapshot。

例如：

```text
ResearchWork

work_ref
run_ref
kind
producer_ref

objective {
    target
    purpose
    constraints
    context
    owner exclusions
}

priority
bounds
budget attribution
state
```

也就是说：

> Objective 是 Work 的一个不可变组成部分，而不是另外一个生命周期实体。

只有以后真的证明 Objective 需要独立复用，才拆出去。

---

# 五、HandoffBundle 不作为长期 V3 架构

之前 `HandoffBundle` 的出现，本质上是因为：

```text
ResearchLoop
```

和：

```text
Semantic Shadow Pipeline
```

属于两个世界。

进入 V3 后，不应该永久保留这座桥。

长期目标应该直接变成：

```text
Evidence
   ↓
SemanticEngine
   ↓
RunSemanticState
   ↓
ResearchRunState
```

而不是：

```text
Semantic Snapshot
↓
HandoffBundle
↓
GapProducer
↓
Objective
↓
Work
```

V3.0 迁移期间如果需要临时 projection，可以有内部对象，但不要把：

```text
PropositionResearchHandoffBundle
```

发展成一套长期 public architecture。

---

# 六、RunState 是 V3 最核心的新增东西

V3.0 首先只解决这一件事：

> **一个 ResearchRun 此刻到底处于什么状态？**

定义：

```text
ResearchRunState
```

它不是复制所有数据，而是整个 run 的 canonical state/index。

大致包含：

```text
run identity
phase

current research objectives

evidence universe refs

semantic state ref

verification state

open gaps

known limitations

current / pending work refs

budget state

termination state

state version

state hash
```

注意：

它不需要直接塞进去：

```text
所有网页正文
所有 Evidence quote
所有 AP 全字段
所有 C1/C2 artifact 内容
```

这些仍然通过 immutable refs 指向已有产品。

---

# 七、只允许一个 Run-State Reducer

现在 V2.3 最大的问题就是 page-scoped semantic state 无法自然成为 run-scoped state。

V3 必须引入一个清楚的：

```text
RunStateReducer
```

但它是 **service/reducer**，不是第六个一等领域实体。

逻辑：

```text
Current ResearchRunState
+
New durable execution result
+
New semantic state
        ↓
RunStateReducer
        ↓
Next ResearchRunState
```

以后 scheduler 绝对不能再自己拼：

```text
page snapshot
+ B1 artifact
+ C2 artifact
+ derived index
+ target state
```

所有 run-level state 都只能来自 reducer。

这能从根本上解决刚才导致 LEVEL 3 的问题。

---

# 八、SemanticEngine 对外只暴露一个稳定接口

V2 内部已经够复杂：

```text
Claim
AP
Formation
Grounding
Identity
A2
A3
B1
B2
C1
ConflictScope
C2
Gap
```

这些都保留。

但 Orchestrator 不应该知道这些内部执行细节。

V3 对外尽量抽象成：

```text
SemanticEngine.evaluate(
    previous_semantic_state,
    new_evidence,
    execution_context
)

→ SemanticStateSnapshot
```

内部仍然运行现有 V2.3 全套逻辑。

外部只看到：

```text
semantic state version
verification
groups
conflicts
gaps
limitations
provenance
completion status
```

这会大幅降低 V3 控制面的复杂度。

# 九、V3 persistence 也要主动收缩

长期原则：

```text
DB
= mutable lifecycle / scheduling / recovery

Artifact
= immutable semantic/state products
```

数据库核心尽量只保留：

```text
ResearchRun

WorkAttempt

```

Artifact 主要保留：

```text
ResearchRunStateSnapshot

```

以及真正必要时：

```text
SemanticExecutionRecord
```

不要一开始建立：

```text
Objective table
Handoff table

Gap truth table
Proposition DB
```

# 十、Authority 架构大幅简化

之前 V2.4 为了让 Shadow 成为 authority，设计过：

```text
InputManifest
StageCompletionRecord
ExecutionProductsComplete
ExecutionReceipt
AuthorityView
```

这些概念有合理性，但放到 V3 全部实现会太重。

V3.2 建议先尝试压缩成一个：

```text
SemanticExecutionRecord
```

它只需要证明：

```text
execution_ref
work_attempt_ref
input_state_ref/hash
new_evidence_refs/hash
semantic_engine_version

status:
COMPLETE
INCOMPLETE
FAILED

output_semantic_state_ref/hash

failure/deferred/budget status
```

如果：

```text
COMPLETE
+
input/output hashes valid
```

那么该 semantic state 可以进入 `RunStateReducer`。

不再额外建立：

```text
ProductsComplete
→ Receipt
→ AuthorityView
```

三四层包装。

如果后面真实测试证明缺 stage-level provenance，再补，而不是提前全做。

# 十一、Work 只保留最少两种

V3.1 初始不要建立十几个 WorkKind。

先只有：

```text
LEGACY_RESEARCH
PROPOSITION_GAP
```

甚至后面 Planner 完成迁移后，可能进一步简化成：

```text
RESEARCH
```

通过 producer/purpose 区分。

Recovery 不一定成为独立 WorkKind，可以是：

```text
same Work
→ new WorkAttempt
```

这样比：

```text
LEGACY
GAP
RECOVERY
FOLLOW_UP
CONFLICT
CORROBORATION
SCOPE
CONTEXT
...
```

干净很多。

Gap 类型仍然属于 semantic Gap，不需要复制成 WorkKind。

# 十二、Legacy 双轨必须有退出计划

这是防臃肿最重要的一条。

V3 初期：

```text
旧 run
→ Legacy ResearchLoop

新 V3 run
→ ResearchOrchestrator
```

可以接受。

但这只能是迁移状态。

不应该长期形成：

```text
Legacy scheduler
+
V3 scheduler
```

V3.1 验证完 legacy equivalence 后：

```text
Planner
↓
ResearchWork
↓
ResearchOrchestrator
```

应该成为新 run 唯一路径。

旧 ResearchLoop 只用于：

> 历史 run resume compatibility。

最终不能再新增功能到旧 loop。

# 十三、Mode 也要简化

之前容易出现：

```text
LEGACY / UNIFIED
×
OFF / SHADOW / ACTIVE
```

产生很多组合。

V3 不建议长期保留这种 mode matrix。

更简单：

### 旧 run

```text
orchestrator_version = V2_LEGACY
```

继续旧模式。

### 新 run

```text
orchestrator_version = V3
```

全部进入新架构。

V3 内部 semantic authority 的成熟过程通过：

```text
feature readiness
```

或内部 flag 控制即可。

不要发展成长期的 6～9 种运行模式。

# 十四、重新规划后的 V3 只保留四个阶段

## V3.0 — Run-State Consolidation

唯一目标：

> 从 page/evidence incremental state 建立 coherent run state。

新增核心概念只有：

```text
ResearchRunState
```

加一个：

```text
RunStateReducer
```

service。

SemanticEngine 对外接口开始形成。

不做 Scheduler。

不做 Gap active research。

不做 Work。

成功标准：

```text
Evidence update
↓
SemanticEngine
↓
SemanticStateSnapshot
↓
RunStateReducer
↓
ResearchRunState vN+1
```

且 crash/resume 后能重建同一 state。

### V3.0 STOP

如果必须：

- 重写 V2.3 semantic meaning；
- 建完整 Proposition relational DB；
- 复制一套新的 semantic truth store；

则 STOP。

# 十六、V3.2 — Semantic State Authority

这一阶段解决：

> 什么 semantic state 可以正式进入 RunState。

核心新增最好只有：

```text
SemanticExecutionRecord
```

链路：

```text
WorkAttempt
↓
Evidence durable
↓
SemanticEngine
↓
SemanticExecutionRecord
↓
SemanticStateSnapshot
↓
RunStateReducer
```

SHADOW 的概念在这里逐渐退出新 V3 run。

对于新 V3 run：

```text
SemanticEngine
```

正式成为架构的一部分，而不是 sidecar。

旧 V2 run 仍保持旧行为。

### V3.2 STOP

如果必须改变：

```text
A2/A3
B1/B2
C1/C2

```

语义才能取得 authority，则 STOP。

# 十七、V3.3 — Autonomous Gap Closure

到这里才完成原 V2.4 未完成部分。

完整闭环：

```text
ResearchRunState
↓
Gap
↓
GapResearchIntent
↓
ResearchWork
↓
WorkAttempt
↓
Search / Reader
↓
Evidence
↓
SemanticEngine
↓
New SemanticState
↓
New ResearchRunState
↓
Gap re-derivation
↓
CLOSED / OPEN / BLOCKED / EXHAUSTED
↓
Continue / Stop
```

这里只需要新增少量：

```text
Gap reconciliation
Semantic progress evaluation
Continuation policy
```

不要再新增一整套 Gap runtime。

# 十八、Gap closure 继续坚持 formal semantics

V3.3 仍然不能因为：

```text
搜索成功
网页打开
Reader 成功
Evidence 数量增加
```

就判断 progress。

Progress 仍然必须来自 RunState 的正式变化，例如：

```text
eligible SUPPORTS 新增
independent owner 新增
conflict resolution 改善
scope completeness 改善
context ambiguity 消除
verification 改善
Gap 消失
```

这样 V2 已经建立的严谨性全部保留下来。

- autonomous loop；

```text
query quality
```

```text
Post-V3 Hardening
```

不要现在先创建 V3.4 / V3.5。

# 二十一、哪些以前设计过的东西降级为“内部实现细节”

# 二十四、V3 迁移原则

V3 不应该一次性把旧代码全部删除。

顺序应该是：

```text

↓
Legacy capability adapter
↓
equivalence tests
↓
新 run 全部走 V3
↓
旧 loop 只负责旧 run resume
↓
稳定后再决定是否移除 legacy code
```

所以：

> 兼容旧数据，但不要永久兼容旧架构。

这是很重要的区别。

# 二十五、V3 完成的三个必须 E2E

最终不要用“文件数、类数、测试数”定义 V3 成功。

只看三个核心闭环。

**场景 A：缺支持**

```text
unsupported proposition
↓
Gap
↓
Work
↓
new evidence
↓
semantic update
↓
supported
↓
Gap gone
↓
stop
```

**场景 B：冲突**

```text
conflicted
↓
conflict research
↓
new evidence/context
↓
ConflictScope complete
↓
resolved
↓
Gap closed
```

```text

↓
bounded attempts
↓
no semantic progress
↓
EXHAUSTED / BLOCKED
↓
no infinite loop
↓
report limitation
```

# 二十六、重新冻结的 V3 Roadmap

最终我建议就定成：

| 阶段 | 正式名称 | 只解决什么 |
|---|---|---|
| **V3.0** | **Run-State Consolidation** | 建立唯一 run-level canonical state |
| **V3.1** | **Unified Research Orchestrator** | Work + Attempt + Scheduler + Resume |
| **V3.2** | **Semantic State Authority** | Evidence → authoritative SemanticState → RunState |
| **V3.3** | **Autonomous Gap Closure** | Gap → Work → Evidence → Gap closure → Continue/Stop |
| **V3 RC** | **Autonomous Research Validation** | Recovery、quality、cross-family、hardening 判断 |
| **Post-V3** | Optional Optimization | 仅数据驱动 |

这次我认为比上一版更加适合你现在的项目。

最大的变化不是阶段名称，而是我们明确决定：

> **V3 不再继续增加桥接层，而是主动删除架构层级。**

最终项目的核心应该从过去的：

```text
很多不同的 state / target / snapshot / adapter
```

收敛成：

```text
ResearchRunState
ResearchWork
WorkAttempt
ResearchOrchestrator
SemanticEngine
```

五个中心概念。

这样 V3 不仅完成 V2 留下的自主闭环问题，也会成为这个项目的一次真正的**架构收敛和瘦身**。



对，这一点必须作为 V3 的最高约束。**架构瘦身不能以功能缩水、证据链变弱、验证标准降低为代价。**

前面说的“减少中间层”，准确含义应该是：

> **减少重复的控制层、桥接层和状态包装；保留甚至强化真正影响研究正确性的语义层、证据层和验证层。**

也就是说，V3 追求的不是“代码越少越好”，而是：

> **最少必要架构 + 完整功能闭环 + 不降低研究准确性。**

我建议把 V3 的总体原则正式修正成下面这套。

## V3 的三个同级目标

以后不能只看“自主闭环”和“架构瘦身”，而应该同时满足：

```text
目标 1：Autonomy
Question
→ Research
→ Evidence
→ Verification
→ Gap
→ New Research
→ Re-verification
→ Stop

目标 2：Accuracy
每个关键判断必须来自正式 Evidence / Semantic contract，
不能因为架构简化而退回 heuristic。

目标 3：Consolidation
消除重复 scheduler、重复 state、重复 authority wrapper，
但不删除真正承担语义正确性的能力。
```

优先级实际上应该是：

```text
研究正确性
    >
功能闭环完整性
    >
架构简洁度
```

如果为了“少一个对象”会降低正确性，那就保留那个对象。

---

## 哪些东西绝对不能因为瘦身而删除

V2 已经建立的这些能力应该视为 **V3 的准确性基础设施**：

```text
Atomic Proposition
TruthConditionContext
Target Formation Fidelity

Source Grounding
Typed-value Grounding
Polarity Grounding

AP ↔ Source Identity
AP ↔ AP Identity

A2 Comparability
A3 Semantic Relation

B1 Support Grouping
B2 Independent Corroboration

C1 Contradiction Detection
ConflictScopeCompleteness
C2 Proposition Verification

Evidence Reliability

PropositionResearchGap
GapResearchIntent
```

这些不是“臃肿”。

它们分别在防止：

```text
把相似说法误认为相同命题
把不同时间/范围的数据错误比较
把同一来源多个页面当独立佐证
把 related 当 supports
把数值差异随便判冲突
把局部检查误认为冲突已完整排查
把搜索结果当事实
把证据数量当验证质量
```

所以这部分应该继续 **frozen + reusable**。

真正该砍的是：

```text
重复 snapshot
重复 handoff wrapper
重复 authority projection
旧/新双 scheduler
旧/新双 continuation
为兼容接口伪造的 target
只做转发而没有独立语义价值的 service
```

---

# ResearchRunState 也不能变成“简化后的真值大杂烩”

这一点尤其重要。

`ResearchRunState` 应该是**索引和协调层**，而不是重新自己计算 semantic truth。

比如：

```text
ResearchRunState
{
    semantic_state_ref,
    evidence_state_ref,
    open_gap_refs,
    active_work_refs,
    budget_state,
    termination_state,
    version/hash
}
```

它可以告诉 Orchestrator：

> 当前有 3 个 open gaps。

但它不能自己通过：

```text
evidence_count >= 2
```

得出：

> VERIFIED。

验证结论仍然必须来自 C2。

同理：

```text
ResearchRunState
```

不能因为有两个不同 URL 就自己判断：

> independent corroboration satisfied。

那仍然必须来自 B2。

所以应该始终保持：

```text
SemanticEngine
= 研究事实 / semantic truth producer

ResearchRunState
= 当前正式状态的 canonical projection

ResearchOrchestrator
= 根据状态决定下一步做什么
```

三者严格分开。

---

# SemanticEngine 的“封装”也不是黑箱降级

前面我建议 V3 对外把 V2.3 包装成：

```text
SemanticEngine.evaluate(...)
```

但这只是**架构接口收敛**。

内部仍然应该完整运行：

```text
Evidence
↓
Claim / AP
↓
Formation
↓
Grounding
↓
Identity
↓
A2
↓
A3
↓
B1
↓
B2
↓
C1
↓
ConflictScope
↓
C2
↓
Gap derivation
```

不是把这些替换成一个：

```python
score = semantic_engine(evidence)
```

那样反而会严重损害研究准确性。

---

# Authority 也不能为了简化完全取消

之前说可以把：

```text
Manifest
StageCompletion
ProductsComplete
Receipt
AuthorityView
```

尽量收敛。

这里要增加一个限制：

> **可以合并对象，但不能合并掉它们代表的正确性条件。**

例如最后只有一个：

```text
SemanticExecutionRecord
```

也可以。

但它必须仍然能够证明：

```text
输入到底是什么
输入 hash 是否一致
消费了哪些 Evidence
用的 semantic engine version
required semantic work 是否全部执行
有没有 NOT_PROCESSED_BUDGET
有没有 FAILED / deferred work
输出的 SemanticState 是哪个
输出 hash 是否匹配
```

所以是：

```text
5 个对象
→ 1 个对象
```

而不是：

```text
5 类正确性保证
→ 只剩一个 status="complete"
```

这是完全不同的。

---

# V3.0：首先保证“状态准确”，而不是只保证“有 RunState”

V3.0 的验收条件应该加强。

不能只是：

> 成功生成 ResearchRunState。

而必须证明：

```text
同一 Evidence universe
+
同一 semantic engine version
+
同一正式配置

无论：

连续运行
crash 后恢复
不同实例恢复
增量更新后 rebuild

都得到语义等价的 RunState。
```

需要重点验证：

```text
没有漏 Evidence
没有混入旧 snapshot
没有跨版本 artifact 混配
没有 page A 的 C2 + page B 的 B1 这种组合
没有 duplicate Evidence 改变结论
```

所以 V3.0 的核心其实应该叫：

> **Run-State Consolidation + Consistency**

而不仅仅是 State。

---

# V3.1：Work 调度不能损害研究质量

统一 Orchestrator 之后，也不能为了执行方便，把 GapIntent 简化成普通搜索关键词。

例如：

```text
MISSING_INDEPENDENT_CORROBORATION
```

不能变成：

```text
搜索一下相同主题
```

它仍然必须保存：

```text
target proposition
required SUPPORTS purpose
excluded owner keys
source independence requirement
scope/context constraints
```

`CONFLICT_RESOLUTION` 也不能变成：

```text
再找更多资料
```

而应该保留：

```text
conflicting sides
comparison context
time/version/scope
disambiguation objective
```

所以可以把 Objective 内嵌到 `ResearchWork`，但 Work 内部必须保留**结构化 objective snapshot**。

例如：

```text
ResearchWork
├─ kind
├─ producer_ref
├─ target_refs
├─ purpose
├─ evidence_requirements
├─ owner_constraints
├─ typed_context
├─ scope
├─ priority
└─ bounds
```

不能只剩：

```text
query = "search ..."
```

---

# V3.2：研究准确性最重要的一道门

这一阶段应该增加一个正式原则：

> **只有完整、可验证的 SemanticExecutionRecord 输出，才能更新 authoritative RunSemanticState。**

比如：

```text
COMPLETE semantic execution
+
UNKNOWN result
```

是合法的。

因为研究本身确实可能无法确定。

但是：

```text
部分 evidence 没处理
+
budget exhausted
+
stage skipped
```

不能因为已经产生一个 C2 对象，就升级 authoritative state。

所以仍然保持：

```text
semantic uncertainty
≠
execution incompleteness
```

这是 V3 准确性的核心原则之一。

---

# V3.3：自主闭环绝不能优化成“搜到东西就继续/停止”

最终 Gap Closure 仍然坚持 V2 的正式规则。

例如：

### MISSING_SUPPORT

只有新的正式：

```text
eligible SUPPORTS
```

进入 semantic state，并导致 Step 1 不再产生原 Gap，才能关闭。

### Independent Corroboration

必须真正出现：

```text
new independent source_owner_key
```

不是不同 URL。

### Conflict Resolution

必须同时满足：

```text
formal conflict state 改变
+
bounded ConflictScope completeness 满足
```

不是“支持材料更多”。

### Context Disambiguation

必须让：

```text
A2 comparability / typed context
```

正式改变。

不是 LLM 觉得“看起来解释清楚了”。

这部分不能因为 V3 简化架构而动摇。

---

# V3 RC 也应该把“准确性”作为第一类指标

以后 V3 RC 不应该只验证：

```text
是否能自动跑完
是否 crash
是否 resume
```

还需要至少看四类指标：

```text
1. Evidence grounding correctness

2. False SUPPORTS / False CONTRADICTS rate

3. Gap closure precision
   —— 不能错误提前关闭

4. Autonomous stopping correctness
   —— 不能因为预算/失败/未知状态伪装成“研究完成”
```

对于 Deep Research Agent 来说：

> **宁可保守地说“还不能确认”，也不能为了闭环率而错误宣称已经验证。**

继续保持 fail-closed。

---

# 所以我建议把 V3 Roadmap 最终调整成这版

| 阶段 | 正式名称 | 核心目标 |
|---|---|---|
| **V3.0** | **Run-State Consolidation & Consistency** | 建立唯一、一致、可恢复的 run-level state |
| **V3.1** | **Unified Research Orchestrator** | Work + Attempt + Scheduler，同时保留结构化 research objective |
| **V3.2** | **Authoritative Semantic State** | Semantic execution 完整性 + authoritative SemanticState |
| **V3.3** | **Autonomous Claim-Driven Closure** | Gap→Work→Evidence→Verification→Closure→Continue/Stop |
| **V3 RC** | **Autonomy + Accuracy Validation** | 同时验证自主能力、恢复能力和研究正确性 |

这里比上一版多强调了两个词：

```text
V3.0:
Consistency

V3 RC:
Accuracy
```

这是必要的。

---

## V3 的总设计准则可以最终冻结成一句话

> **Simplify orchestration, not semantics.**

中文就是：

> **简化编排，不简化研究判断。**

或者更完整一点：

> **V3 应减少重复控制层和中间包装，但不得减少证据、语义比较、独立佐证、冲突、验证、Gap 与执行完整性所提供的正确性保障。**

所以以后判断“这个东西要不要删”，不能问：

> 能不能少一个类？

而应该问：

> **它是在提供独立的正确性保证，还是只是为了连接旧架构？**

前者保留。

后者优先合并或淘汰。

这样 V3 才能同时做到两件事：**系统不越来越臃肿，同时研究功能和准确性不倒退。**
