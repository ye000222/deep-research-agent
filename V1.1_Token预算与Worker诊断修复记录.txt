三、本次代码修复
----------------

- 每次 Evidence 模型调用前读取 Run Token 余额并执行确定性 Guard。
- 为报告 Writer 预留 3,000～10,000 Token，余额不足时停止新增抽取并进入带限制写作。
- 普通 Extractor Context 输入上限 6,000、输出上限 3,500 Token。
- Compact Extractor Context 输入上限 3,000、输出上限 1,800 Token。
- Evidence Extractor 禁用 Adapter 内部不可见的自动双次再生成，改由服务层执行一次受预算约束的 Compact Retry。
- 首次失败、结构修复和空结果补救的 Usage 均合并计入 Run。
- 终态和写作态保留 Provider 返回后的真实 Token 超额；研究态仍拒绝超限。
- Worker 先记录原始异常，再 best-effort 同步终态；同步失败不再替换原始 traceback。
- 前端从 planner/evidence/writer 分项计算真实模型 Token，并显示明确预算诊断。
