====================================

审查日期：2026-08-31
审查记录版本：V1.7
审查对象：DeepResearch_Agent_V1_开发计划.txt 与当前代码仓库
审查原则：只把已经存在于代码、数据库 Migration 或可重复验证结果中的能力列为“已完成”；计划文档中的目标不等于实际完成。

审查结论：当前项目已经打通“模型配置 → Planner → 多轮搜索 → 网页读取 → 证据抽取 → 基础 Evaluation → 报告生成 → 引用展示”的可运行纵向链路。StateGraph 已从单个粗粒度 Research Loop 节点升级为可在每轮研究后条件回环的 iteration-level Graph；每轮会生成可重放的 Coverage Map、Information Gain、关键缺口和继续/停止说明。Evidence Graph 基础闭环已完成：Claim / Evidence / Chunk / Snapshot 原子绑定、确定性 supports / contradicts / supplements 关系、独立来源 Conflict 门槛、Graph API 和 Citation Snapshot 外键链均已进入运行时；当前主要缺口转为 Context Budget Manager、研究经验 Memory、工具级细粒度节点、完整冲突消解和语义 Evaluation。

一、总体判断
------------

当前定位：可以端到端演示的 Evidence-driven Research Agent，已具备 iteration-level 状态图、持久化恢复基础、Coverage Map、确定性 Information Gain，以及 Claim → Evidence → Chunk → Snapshot → Citation 的运行时链路和基础 Claim Relation / Conflict 管理；还不是开发计划中完整的“Context Budget + Research Memory + Tool Policy + Semantic Evaluation”系统。

粗略完成度：

- 按可运行 Demo 计算：完成度较高，主链路可以演示
- 按完整 V1 Release Gate 计算：约 62%
- 已完成主链路：基础工程、PostgreSQL、BYOK、Planner、搜索、网页读取、证据校验、iteration-level StateGraph、Coverage/Information Gain、报告和引用
- 最大缺口：Context Budget Manager、研究经验 Memory、工具级细粒度节点、统一 Tool Calling、完整冲突消解和语义 Evaluation

本轮新增的实际进展：

- StateGraph 已调整为 Planner → Research Iteration ↻ → Report Writer；每轮 Evaluation 后由条件边自动继续或进入写作
- Worker 使用官方 AsyncPostgresSaver 编译和执行 Graph
- Graph 使用 thread_id=run_id 和 durability=sync 保存 Planner、每轮 Research Iteration 与 Writer 边界 Checkpoint
- 新增 research_state_snapshots 和 research_state_patches 两张业务表
- 新增轻量 ResearchState 初始化、StatePatch 投影、版本校验、State Hash 和 Patch 审计
- accepted Evidence 和 Research Gap 可投影到 State 的 Known / Gaps
- 新增 GET /api/v1/research-runs/{run_id}/state
- 失败、取消、恢复边界会同步公开 ResearchState；恢复时会清理旧 stop_reason
- completed_with_limitations 使用独立机器可读 StopReason，不再误报为 budget_exhausted
- Planner 重试逻辑迁移到 ResearchGraphService，避免 Worker 和 Graph 出现两套编排逻辑
- 新增按 Question/Priority/独立来源计算的 Research Coverage Map
- 新增确定性 Information Gain、低增益连续轮次和可解释继续/停止事件
- quality_met、sources_exhausted、stagnation 使用不同终止原因和报告限制
- Evidence Graph 新数据在 Evidence 保存事务内创建/复用 Claim、Source Snapshot 与 Source Chunk，并绑定可追溯外键
- accepted Evidence 若无法在网页正文定位 Exact Quote，会由服务端降级拒绝
- 新增 GET /api/v1/research-runs/{run_id}/evidence-graph，并在现有 Evidence API 返回 claim_id / snapshot_id / chunk_id
- 新增历史 Evidence Graph 回填 CLI，默认 dry-run；已在真实 PostgreSQL 完成 144 条历史 Evidence 回填与幂等复查
- 新增确定性 Claim Relation v2：同实体/指标范围门槛、独立 source_owner_key Conflict 门槛、假冲突回归测试和 stale edge 协调删除
- Graph API 已返回 Claim Edge 与 Conflict；历史关系重建为 7 条 supplements、0 条伪 conflicts，二次 apply 零变更
- Report Citation 新增 claim_id / snapshot_id / chunk_id；Citation API 返回 Snapshot Hash 与 Chunk 字符定位

P6 Research Loop 与 Evaluation：部分完成

已完成：

- 自动多轮循环；每轮成为独立 StateGraph Super-step 并可 Checkpoint
- 每个问题最多两次补充尝试
- 自动读取网页和抽取证据
- Coverage Map 按问题优先级、证据数和独立来源域名计算 0 / 0.5 / 1 维度状态

- 每轮记录 information_gain、low_information_gain_streak、critical_gaps 和公开决策说明
- Source Quality 0.75、Cross Validation 0.70、Priority 1 Coverage 0.80 已进入质量停止硬门

九、根据《新内容.txt》重新确定的当前方向
------------------------------------------

新的产品定位：

Evidence-Aware & Memory-Aware Deep Research Agent，即面向长周期研究的证据驱动、自适应上下文管理 Research Agent。

V1 不再以“功能数量最多”作为推进目标，而只优先打磨三个能形成辨识度、能现场验证的核心亮点：

1. Evidence Graph
   - Claim、Evidence、Source Snapshot、Source Chunk、支持/反驳/补充/派生关系可追溯。
   - 冲突不静默选择；按时间、地区、单位、定义和来源独立性生成 Conflict。
   - 报告引用必须沿 Claim → Evidence → Chunk → Snapshot → URL 回溯。

2. Coverage-driven / Information-Gain Research Loop
   - Coverage 按研究维度和 Acceptance Criteria 计算，必须能解释每个维度的已知、未知和证据数量。
   - 每轮记录新增 Evidence、Claim、独立 Source、Coverage 提升和重复信息，形成 Information Gain。
   - 继续、补搜、重规划或停止由 Coverage、关键 Gap 和边际信息增益共同决定，而不是只按搜索次数停止。

3. Context Budget Manager
   - 按模型 Context Window 为 State、当前 Gap、Evidence、Working/Task Memory 和输出预留预算。
   - 对候选内容排序、去重、压缩和重新检索；关键数字、实体、日期、Exact Quote、Citation ID 和高严重度冲突不得丢失。
   - 每次调用要有可追溯的 Context Manifest、Token 使用和压缩记录。

当前代码对新方向的映射：

- iteration-level StateGraph、State Snapshot/Patch 和基础 Evidence/Gap Loop：已完成或部分完成。
- Evidence Graph 的 Claim/Snapshot/Chunk/Claim Edge/Conflict ORM 与 Migration、新证据运行时原子绑定、自动关系协调、Graph API、历史回填和 Citation Snapshot 结构链均已在真实 PostgreSQL 验证；完整语义关系、Conflict Resolution 与非空历史 Citation 运行验证仍待完成。
- 可解释 Coverage Map 和 Information Gain：已完成基础可运行版本；Acceptance Criteria 子维度、Owner 独立性和语义信息增益仍未完成。
- Context Manifest、动态预算、压缩和 provenance：未完成。
- 当前 Run 的 Working/Task Memory 检索和固化：未完成。
